# CSV to Clone Hero

Turn music-library exports or Spotify data into a Clone Hero / YARG song
library: normalize tracks, find playable charts on
[Chorus Encore (Enchor)](https://enchor.us), score the matches, and organize
the `.sng` charts into folders the game scans directly.

There are **two ways to run it**:

| Mode | Who it's for | Command |
|------|--------------|---------|
| **Local (single-user)** | Run on your own PC; downloads land on that PC | `WEB_INTERFACE.bat` or `python -m csv_to_clonehero web` |
| **Cloud (multi-user)** | The hosted web product behind Cloudflare | `python -m csv_to_clonehero serve` (or Docker) |

Everything below is the same matching/scoring engine under both.

## 1. Local single-user (run on your own computer)

### Quick start (Windows)

1. Install **Python 3.11+** from <https://www.python.org/downloads/> and tick
   **"Add python.exe to PATH"**.
2. Double-click **`WEB_INTERFACE.bat`**. First run sets up a `.venv` (a minute
   is normal), then a browser opens at `http://127.0.0.1:8765`.
3. Use the source-neutral home page to upload a supported export, or connect
   Spotify and choose playlists / Liked Songs. `/advanced` remains available for
   the full CSV/iTunes review flow.
4. Review candidates and export to a Clone Hero Songs folder, or download a ZIP.

The source-neutral home page's catalog-backed matching requires an operator-
managed `catalog/enchor.jsonl` snapshot. Without a complete snapshot it reports
that the catalog is unavailable rather than claiming that songs have no charts.
The snapshot is generated by `catalog-export` and is ignored by Git because the
current file is too large for a normal GitHub repository. The legacy `/advanced`
flow can search Enchor directly without that local snapshot.

SoundCloud is optional. Set `SOUNDCLOUD_CLIENT_ID` and
`SOUNDCLOUD_CLIENT_SECRET`, register
`http://127.0.0.1:8765/api/auth/soundcloud/callback` with SoundCloud, then use
**Connect SoundCloud** in the Spotify workspace. Select SoundCloud playlists or
Liked Tracks before discovery to combine both libraries. SoundCloud audio is
never downloaded.

`/advanced` is **CSV & music-file import**: add Spotify CSV or iTunes/Music
TXT/XML exports, preview chart matches, review choices, then download selected
charts. The no-browser flow is: drop export files into `input_playlists`, then
`DRY_RUN.bat` → `BUILD_LIBRARY.bat`.

### Spotify Client ID (one-time, ~2 minutes)

1. Go to <https://developer.spotify.com/dashboard> → **Create app**.
2. Add redirect URI: `http://127.0.0.1:8765/api/auth/spotify/callback`
3. Put the **Client ID** in `config.yaml` (created on first run):
   ```yaml
   spotify:
     client_id: "YOUR_CLIENT_ID"
   ```
   There is **no client secret** — the app uses PKCE. The token is kept in the
   OS keyring (single-user mode only).

### Using it from another computer on your Wi-Fi

```powershell
python -m csv_to_clonehero web --lan            # prints a private token URL
```
Sign in **on the host first** (the OAuth callback is loopback-only), then open
the printed `http://<host-ip>:8765/?access_token=...` link on the other device.
For a different network, use a tunnel:
```powershell
python -m csv_to_clonehero web --lan --public-url https://<your-https-tunnel>
```
and register `<tunnel>/api/auth/spotify/callback` as a redirect URI.

## 2. Cloud multi-user product (the hosted web app)

The `server/` package is the public product: real Spotify login, per-user
identity, background jobs, and browser-only ZIP downloads. Public discovery
requires Spotify sign-in and a fresh Enchor preflight. See
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) and
[`docs/runbook.md`](docs/runbook.md).

### Run locally (development)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

# set required env vars (see .env.example), then:
.\.venv\Scripts\python.exe -m csv_to_clonehero keys    # generate secrets
.\.venv\Scripts\python.exe -m csv_to_clonehero serve   # waitress on :8000
```

### Production (Docker)

```bash
cp .env.example .env      # fill in real values (never commit .env)
docker compose up -d --build
```

Required environment variables (see [`.env.example`](.env.example)):

| Variable | Meaning |
|----------|---------|
| `SPOTIFY_CLIENT_ID` | public Spotify app id (PKCE, no secret) |
| `SOUNDCLOUD_CLIENT_ID` | optional SoundCloud OAuth client id |
| `SOUNDCLOUD_CLIENT_SECRET` | optional SoundCloud OAuth client secret |
| `APP_BASE_URL` | public HTTPS origin, e.g. `https://charts.ryo-nd.com` |
| `SECRET_KEY` | session signing key (`python -m csv_to_clonehero keys`) |
| `TOKEN_ENCRYPTION_KEY` | Fernet key encrypting per-user refresh tokens |
| `NOTIFICATIONS_API_KEY` | optional transactional email key |
| `GOFUNDME_URL` | optional GoFundMe campaign URL |

Never put secrets in `config.yaml` — it is gitignored and untracked.

## How matching works

Every unique song is scored **0–100** using artist/title similarity, remaster
and edition normalization, instrument compatibility, chart quality, and
penalties for wrong-version charts (covers, live, remixes).

| Score | Outcome |
|-------|---------|
| 90–100 | **Auto-accepted** |
| 70–89  | **Review** — shown in UI + `reports/review_needed.csv` |
| < 70   | **Rejected** — `reports/no_matches.csv` / `reports/rejected_candidates.csv` |

Quality gates hard-reject charts with no playable content (no instruments and
no difficulty ratings). Thresholds are in `config.yaml`.

- **Catalog-first search**: artists with 3+ unique tracks get one artist query;
  their songs are scored locally, with automatic per-song fallback.
- **Artist expansion** (optional): adds more charts by your artists — up to 50
  for artists with 5+ songs, 25 for 2–4, 10 for 1.
- **Guitar-first**: only 5-fret lead guitar charts by default; drums/vocals-only
  and modcharts are excluded unless allowed in `config.yaml`.
- **Storage budget**: default 48 GiB; exact songs outrank expansion when space
  runs out.
- Results are cached 7 days. Enchor rate-limits hard (~1–2 req/s per IP), so
  the app is deliberately slow/polite and resumable.

### Folder layout (default `hybrid`)

```
<Artist>/<Album>/<Artist> - <Title> [<Charter>].sng     exact songs
<Artist>/Singles/...                                     no-album exact songs
<Pack Name>/<Artist> - <Title> [<Charter>].sng           artist-expansion songs
```

Only `.sng` files live in the library root; reports stay in `reports/`.
Alternatives via `library.layout`: `artist_album`, `pack`, `legacy`.

## Reports

Every run writes `reports/`: `master_list.csv` (whole library with match
status), `exact_matches.csv`, `artist_expansion.csv`, `review_needed.csv`,
`no_matches.csv`, `rejected_candidates.csv`, `downloaded.csv`,
`download_errors.csv`, `skipped_for_space.csv`, `summary.txt` / `summary.json`,
and Spotify workflow reports such as `spotify_library.csv`,
`spotify_item_statuses.csv`, `spotify_candidates.csv`, `spotify_exports.json`,
and `spotify_scan.json` when that workflow is used.

## Command line

```powershell
python -m csv_to_clonehero web            # local web interface (single-user)
python -m csv_to_clonehero serve          # cloud multi-user app (waitress)
python -m csv_to_clonehero keys           # generate SECRET_KEY / TOKEN_ENCRYPTION_KEY
python -m csv_to_clonehero scan           # parse CSVs only
python -m csv_to_clonehero search         # search + score
python -m csv_to_clonehero expand --dry-run
python -m csv_to_clonehero plan           # compute download plan
python -m csv_to_clonehero build          # full pipeline incl. downloads
python -m csv_to_clonehero report         # regenerate reports
python -m csv_to_clonehero doctor         # check setup
python -m csv_to_clonehero reset-cache    # clear search cache
python -m csv_to_clonehero catalog-export # acquire a local Enchor metadata snapshot
```

## Chart sources & ethics

The only built-in source is **Chorus Encore / Enchor** (`api.enchor.us` search,
`files.enchor.us` download) — the same service used by the official
[Bridge](https://github.com/Geomitron/Bridge) desktop downloader. It does **not**
scrape piracy sites or bypass restrictions. The pipeline is multi-source-ready
(`sources/base.py:ChartSource`); Enchor is currently the only adapter because no
other legitimate public chart API with search + direct download was verified.

Known limitations: Enchor's `md5` identifies a chart but does **not** match the
served `.sng` bytes (validated by size/format, not checksum); it provides no
popularity ranking.

## Development

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest              # offline suite
.\.venv\Scripts\python.exe -m pytest -m integration  # live Enchor (rate-limited)
```

CI: `.github/workflows/ci.yml` runs the offline suite on every push and the live
integration suite on a schedule.

### Repo layout

```
src/csv_to_clonehero/
  config.py          config loading + state DB migration
  models.py          Track / ChartCandidate / ScoreBreakdown
  normalization.py   music-metadata string normalization
  csv_import.py      Spotify CSV + iTunes/Apple Music (.txt/.xml) parsing
  matching.py        scoring engine + quality gates
  planner.py         selection + storage budget
  downloader.py      resumable, validated downloads
  database.py        SQLite state (cache, scores, downloads, multi-user tables)
  reporting.py       reports/ generation
  filesystem.py      safe paths, library layouts
  pipeline.py        scan/search/plan/relocate/build orchestration
  webapp.py          LOCAL single-user web UI (source-neutral home + /advanced)
  spotify.py         Spotify OAuth + API primitives
  spotify_pipeline.py  resumable discovery orchestration
  catalog.py         validated local Enchor catalog reader/exporter
  combined_pipeline.py  source-neutral catalog discovery
  library_pipeline.py   provider import persistence
  diagnostics.py     redacted local run diagnostics
  providers/         Spotify/SoundCloud library adapters
  sources/           ChartSource adapters (base.py, enchor.py)
  server/            CLOUD multi-user product
    web.py             WSGI app factory (public product)
    auth.py            per-user encrypted token store + OAuth
    jobs.py            durable job queue + global worker
    throttle.py        global Enchor egress gate
    downloads.py       short-lived signed ZIP delivery
    notifications.py   job-completion email
    security.py        Fernet token encryption + secret resolution
tests/               pytest suite (offline + integration)
docs/                current architecture, configuration, and operations
browser_export/      optional rendered-metadata SoundCloud userscript
catalog/             local generated Enchor metadata snapshot (ignored)
```

`AGENTS.md` holds deeper operational knowledge (Enchor API behavior, rate
limits, schema details) for AI agents. Contributor-facing guidance is in
[`CONTRIBUTING.md`](CONTRIBUTING.md); security handling is in
[`SECURITY.md`](SECURITY.md).
